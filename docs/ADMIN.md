# Администрирование каталога SecuTar Help

Весь каталог лежит в одном файле: **`data/catalog.json`**.
HTML, CSS и JavaScript при изменении каталога **не трогаются вообще**.

Редактировать файл можно любым удобным способом:

- **в браузере** — на GitHub откройте файл `data/catalog.json`, нажмите иконку
  карандаша (Edit in place) или клавишу `E`; после правки нажмите
  *Commit changes*;
- **в Zed** — откройте папку проекта локально, отредактируйте файл и опубликуйте
  изменения (commit + push);
- **в веб-редакторе github.dev** — на странице репозитория нажмите клавишу `.`
  (точка) или замените в адресе `github.com` на `github.dev` — откроется
  редактор с тем же интерфейсом, что и VS Code.

Изменения попадают на сайт после публикации: автоматически при следующем
push в ветку `main` (см. конец файла — «Как изменения попадают на сайт»).

---

## 1. Структура файла

Файл состоит из двух списков:

```json
{
  "version": 1,
  "updated": "2026-11-28",
  "categories": [ ... дерево категорий ... ],
  "resources":  [ ... плоский список всех ссылок ... ]
}
```

Поле `updated` — просто дата последней правки (для человека), на работу сайта
не влияет.

### Категория

```json
{
  "id": "training",
  "name": "Бесплатное онлайн обучение",
  "order": 1,
  "children": []
}
```

| Поле | Что это |
|---|---|
| `id` | Короткое имя категории латиницей. Используется в адресе сайта. Уникален. Можно менять только пока категорию никто не использует в адресах/закладках |
| `name` | Название, которое видят посетители |
| `order` | Число, порядок показа внутри своего уровня (1 — выше всех) |
| `children` | Подкатегории — такие же объекты. Пустой список `[]` — категория без подкатегорий |

### Ресурс (ссылка)

```json
{
  "id": "dssl-edu",
  "title": "Портал обучения DSSL",
  "url": "https://edu.dssl.ru/",
  "description": "Бесплатные курсы и вебинары по видеонаблюдению и TRASSIR",
  "category": "training",
  "tags": ["обучение", "видеонаблюдение"],
  "order": 1
}
```

| Поле | Что это |
|---|---|
| `id` | Уникальное латинское имя записи. На работе сайта почти не видно, служит «паспортом» записи |
| `title` | Название ссылки |
| `url` | Полный адрес, обязательно с `https://` (или `http://`) |
| `description` | Краткое описание (1 предложение). Необязательно — можно опустить |
| `category` | `id` категории, куда помещается ссылка |
| `tags` | Список тегов. Можно оставить пустым `[]`. Теги показываются на карточках и участвуют в поиске; отдельный список вести не нужно |
| `order` | Порядок показа внутри своей категории |

## 2. Типовые операции

### Добавить ссылку

Найдите в `resources` нужную категорию (ресурсы идут по категориям, внутри —
по `order`) и добавьте новый объект по образцу выше. Следите за запятыми:
между элементами массива запятая есть, после последнего — нет.

Пример — добавить калькулятор в «Калькуляторы архива» (`archive-calc`):

```json
{
  "id": "my-new-calc",
  "title": "Название калькулятора",
  "url": "https://example.com/calc",
  "description": "Что считает",
  "category": "archive-calc",
  "tags": ["калькулятор", "архив"],
  "order": 5
}
```

### Добавить категорию

Корневую — добавьте объект в самый внешний массив `categories` и задайте
следующий свободный `order`:

```json
{
  "id": "misc",
  "name": "Разное",
  "order": 8,
  "children": []
}
```

Подкатегорию — добавьте объект в массив `children` нужной категории:

```json
{
  "id": "misc",
  "name": "Разное",
  "order": 7,
  "children": []
}
```

Сразу после создания категория появится на сайте даже без ресурсов.

### Переместить ссылку в другую категорию

Измените у ресурса поле `category` на `id` новой категории. Например, `"category": "training"` → `"category": "useful"`.

### Удалить ссылку

Удалите весь объект ресурса из `resources` (вместе с запятой после него, если
она остаётся «висящей» — проще всего удалить запятую перед следующим объектом).

### Переименовать категорию

Просто поменяйте `name`. Поле `id` при переименовании менять **не нужно** —
если сменить его, сломаются адреса категорий и ссылки ресурсов.

### Поменять порядок

Измените числа `order`. Меньшее число — выше в списке.

## 3. Частые ошибки и как их избежать

| Ошибка | Признак | Как исправить |
|---|---|---|
| Лишняя или пропущенная запятая | Красная подсветка в редакторе / ошибка JSON | Проверьте запятые между элементами; после последнего элемента запятой быть не должно |
| Неправильные кавычки | Ошибка JSON | В JSON только двойные прямые кавычки `"`; кавычка внутри текста экранируется: `2,5\"` |
| `category` не существует | Сайт покажет ошибку, Action упадёт | Используйте точный `id` категории, он указан рядом |
| Дублирующийся `id` | Валидатор ругается | Дайте записи другой `id`, например добавьте `-2` |
| Кириллица в `id` | Валидатор ругается | В `id` только латиница/цифры/дефис; кириллица допустима в `name`, `title`, `description`, `tags` |

**Важно:** одна ошибочная запись не ломает весь каталог. Сайт пропускает
неправильные записи и показывает остальные, а в консоли браузера пишет, что
пропущено. Но до публикации плохие записи лучше не доводить: валидатор в
GitHub Action остановит публикацию и покажет список ошибок.

## 4. Как изменения попадают на сайт

1. Вы правите `data/catalog.json` и сохраняете изменения в репозиторий
   (Commit → Push, или «Commit changes» на GitHub).
2. GitHub Action `Проверка каталога и публикация`:
   - проверяет файл валидатором `scripts/validate.js`;
   - если всё в порядке — публикует сайт на GitHub Pages (1–2 минуты);
   - если есть ошибки — публикация отменяется, а в закладке *Actions*
     репозитория будет список проблем с указанием, в каком месте файла ошибка.
3. Открыть список проверок: вкладка **Actions** в репозитории → последний
   запуск → шаг «Проверка data/catalog.json».

Проверить файл локально можно командой (если установлен Node.js):

```
node scripts/validate.js data/catalog.json
```

## 5. Полезно знать

- **Адрес категории** строится из её `id`:
  `https://help.secutar.org/#lens-calc`. Поэтому `id` категорий
  лучше не менять после публикации ссылок на них.
- **Теги** на сайте пишутся строчными буквами; регистр в файле не важен —
  поиск и фильтр сравнивают без учёта регистра и буквы «ё».
- **Поиск** ищет по названию, описанию, домену и тегам одновременно.
- Счётчики ресурсов в дереве и панель тегов обновляются автоматически.
