Этот документ — одновременно рабочий план проекта и его основная документация.
Он обновляется по мере выполнения работ. Инструкция для повседневного
администрирования каталога — в файле `docs/ADMIN.md`.

## 2. Архитектура

Сайт — статический: HTML + CSS + чистый JavaScript, без фреймворков, библиотек
и этапа сборки. GitHub Pages отдаёт файлы как есть.

```
help.secutar/
├── index.html              Каркас страницы (менять почти не нужно)
├── CNAME                   Привязка домена help.secutar.org
├── .nojekyll               Отключает обработку Jekyll на GitHub Pages
├── css/
│   └── style.css           Оформление, обе темы Solarized, адаптивность
├── js/
│   └── app.js              Логика: дерево, поиск, фильтры, темы, адресная строка
├── data/
│   └── catalog.json        ★ ВЕСЬ каталог: категории, ссылки, теги
├── assets/
│   └── favicon.svg         Иконка сайта
├── scripts/
│   └── validate.js         Проверка корректности catalog.json (Node.js, без зависимостей)
├── docs/
│   ├── ADMIN.md            Инструкция по добавлению/изменению записей
│   └── PLAN.md             Этот документ
└── .github/
    └── workflows/
        └── deploy.yml      Проверка данных + публикация на GitHub Pages
```

Ключевые принципы:

1. **Данные полностью отделены от кода.** Весь каталог лежит в одном файле
   `data/catalog.json`. HTML, CSS и JS при добавлении ссылок не трогаются.
2. **Две линии защиты от ошибок.**
   - Перед публикацией GitHub Action запускает `scripts/validate.js`. Если в
     данных ошибка — публикация блокируется, в Actions видно, что именно не так.
   - Сайт на своей стороне дополнительно проверяет каждую запись: повреждённая
     запись пропускается, остальной каталог продолжает работать.
3. **Готовность к будущей админке.** Сайт читает данные только из
   `catalog.json` через один слой загрузки. Позже к этому же файлу можно
   подключить бесплатную веб-админку (Decap CMS), которая правит тот же JSON
   и сохраняет изменения прямо в репозиторий — переделывать сайт не придётся.
   Секретов и токенов в клиентском коде нет и не будет.

## 3. Структура каталога

Структура категорий повторяет разделы исходной книги на GitBook **один в один**
(без пустой страницы «Добавить/удалить» и служебной страницы-оглавления).
Теги на сайте остались только на карточках ресурсов и в поиске — в левой
панели их нет.

```
└─ Все ресурсы (корневой пункт, всегда доступен)
   ├─ Бесплатное онлайн обучение
   ├─ Калькуляторы объектива
   ├─ Калькуляторы архива
   ├─ Описание и сравнение RAID
   ├─ Калькуляторы RAID
   └─ Полезное
```

Внутри раздела «Полезное» порядок ресурсов сохранён как в исходной книге:
сначала группа «Системы безопасности», затем «ИТ», затем «Накопители и RAID».

Категории без описаний (по решению владельца). Перенесено 60+ ресурсов.
Примечание: фрагмент с `.bat`-скриптом перезапуска сетевого интерфейса из
раздела «Полезное» в каталог ссылок не входит — это кодовая заметка, а не
ресурс. Если она нужна, позже можно добавить раздел «Заметки» (см. «Дальнейшее развитие»).

## 4. Формат данных `data/catalog.json`

```json
{
  "version": 1,
  "updated": "2026-11-28",
  "categories": [
    {
      "id": "training",
      "name": "Бесплатное онлайн обучение",
      "order": 1,
      "children": []
    }
  ],
  "resources": [
    {
      "id": "dssl-edu",
      "title": "Портал обучения DSSL",
      "url": "https://edu.dssl.ru/",
      "description": "Бесплатные курсы и вебинары по видеонаблюдению и TRASSIR",
      "category": "training",
      "tags": ["обучение", "видеонаблюдение"],
      "order": 1
    }
  ]
}
```

Правила полей:

| Поле | Обязательное | Правило |
|---|---|---|
| `id` | да | Латиница, цифры, дефис; уникален среди всех id |
| `name` / `title` | да | Непустой текст |
| `order` | да | Число; сортировка внутри своего уровня |
| `children` | да (у категорий) | Массив, может быть пустым `[]` |
| `url` | да (у ресурсов) | Полный адрес, начинается с `http://` или `https://` |
| `description` | нет | Краткое описание; можно опустить |
| `category` | да (у ресурсов) | `id` существующей категории |
| `tags` | да (у ресурсов) | Массив строк; можно пустой `[]` |

Особенности поведения:

- Ресурс можно привязать к любой категории, включая корневую.
- Список тегов нигде отдельно вести не нужно — он собирается автоматически
  из ресурсов и отображается в боковой панели.
- Порядок в каталоге задаётся полем `order`; при равных значениях — по названию.

Полная пошаговая инструкция — в `docs/ADMIN.md`.

## 5. Интерфейс

- **Компоновка:** слева дерево категорий («Все ресурсы» + сворачиваемые ветви
  со счётчиками), справа — заголовок категории и карточки ресурсов.
- **Карточка ресурса:** название (ссылка), описание, домен, теги. Ссылки
  открываются в новой вкладке.
- **Поиск:** полнотекстовый, по названиям, описаниям, доменам и тегам;
  регистр и буква «ё» не влияют. Работает вместе с категорией и тегами.
- **Фильтры:** выбор тегов — кликом по тегу на карточке. Активные фильтры
  показываются «чипами» над списком, каждый снимается кликом; есть кнопка
  «Сбросить всё». Есть сообщение «ничего не найдено».
- **Адрес категории:** у каждой категории свой адрес вида
  `https://help.secutar.org/#lens-calc`. Кнопка «Копировать ссылку»
  рядом с заголовком; адрес также можно просто скопировать из строки браузера.
  Обновление страницы и прямой вход по ссылке работают.
- **Темы:** настоящая палитра Solarized. Три режима — системная / светлая /
  тёмная (переключатель в шапке). По умолчанию — системная; ручной выбор
  сохраняется в localStorage.
- **Мобильная версия:** дерево превращается в выдвижное меню по кнопке
  «Меню»; увеличенные зоны нажатия, без горизонтальной прокрутки,
  длинные URL и названия переносятся.
- **Доступность:** семантическая разметка, клавиатурная навигация, состояния
  фокуса, aria-атрибуты у переключателей, ссылка пропуска к содержимому.
- **Шрифт:** Ubuntu (Google Fonts) с системными резервными шрифтами.

## 6. Публикация и домен

1. **DNS** — уже настроен: домен help.secutar.org сейчас обслуживается
   GitHub Pages с этим же репозиторием. Менять DNS не требуется.
2. **CNAME** — файл `CNAME` с доменом лежит в корне репозитория.
3. **Действие владельца (один раз):** в GitHub открыть
   *Settings → Pages → Build and deployment → Source* и выбрать
   **GitHub Actions** (вместо «Deploy from a branch»). Это нужно, чтобы
   заработал автоматический контроль данных перед публикацией.
   После этого каждый push в `main` автоматически:
   проверяет `data/catalog.json` → при успехе публикует сайт → при ошибке
   публикация не выполняется, а в закладке *Actions* видно описание ошибки.
4. **HTTPS** — включается GitHub Pages автоматически для custom-домена;
   проверить: *Settings → Pages* → «Enforce HTTPS».
5. Если рабочий процесс через Actions по какой-то причине не подойдёт, можно
   вернуться к публикации из ветки — сайт будет работать, но ошибочные данные
   тогда будет ловить только сам сайт (второй уровень защиты).
